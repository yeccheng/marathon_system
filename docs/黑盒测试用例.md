# 马拉松赛事管理系统 — 黑盒测试用例表

> **设计方法**：等价类划分 + 边界值分析  
> **统一约定**：成功 `code=200`、`msg=操作成功`；业务/参数失败 `code=500` + 中文 `msg`  
> **鉴权**：除 `/api/login` 外，请求头需携带 `Authorization: Bearer <token>`  
> **前置数据**：库中已有 3 场赛事、7 名选手、14 条报名、10 条成绩（见 `docs/数据库脚本/marathon_system_data.sql`）  
> **优先级**：P0 核心业务 / P1 重要功能 / P2 一般查询

## 六、等价类与边界值说明（答辩可用）

| 分析维度 | 有效等价类 | 无效等价类 | 边界值 |
|---------|-----------|-----------|--------|
| 分页 `pageNum` | ≥1 的整数 | ≤0、非数字 | 第1页；最后一页；超出总页 |
| 分页 `pageSize` | 正整数（如1/5/10） | 0、负数 | `pageSize=1`；刚好等于 total |
| 赛事类型 | 1、2、3 | null、0、4、9 | 1 与 3 |
| 名额 `quota` | ≥1 | 0、负数、null（DB） | `quota=1`；满员（registered=quota）；剩1个名额 |
| 身份证号 | 18位合法格式且唯一 | 空、短于18、重复 | 恰好18位 |
| 报名状态 | status=1 可取消 | 2/3 不可再取消 | 首次取消成功 / 第二次失败 |
| 成绩唯一 | 未录入可录 | 已录入不可再录 | 同一 registration 第1次/第2次 |

## 七、核心业务校验对照（答辩亮点）

| 业务规则 | 对应用例 | 预期中文提示 |
|---------|---------|-------------|
| 同一选手同一赛事不可重复报名（`uk_event_runner`） | REG-002 | 该选手已报名此赛事，请勿重复报名 |
| 名额已满不可报名 | REG-007 | 赛事名额已满，报名失败 |
| 已取消不可再取消 | REG-010 | 该报名已取消或已退赛，不能重复取消 |
| 一场报名只能录一条成绩（`uk_registration`） | RES-002 | 该报名记录已录入成绩，不能重复录入 |
| 有报名的赛事不能删除 | EVT-014 | 该赛事已有报名记录，不能删除 |
| 有报名的选手不能删除 | RUN-014 | 该选手已有报名记录，不能删除 |
| 身份证号唯一（`uk_idcard`） | RUN-006 | 数据库唯一约束失败（code=500） |
